# ADR-007: A price server keeps AODP's prices in Postgres

- **Status:** Proposed
- **Date:** 2026-11-14

## Context

Each visitor's browser asks AODP for its own prices ([ADR-003](003-price-data-strategy.md)). That has limits:

- AODP allows 180 requests a minute per IP address. A visitor who looks at many routes waits on the rate limiter, and AODP gets the same questions from every visitor.
- The 6-hourly price snapshot is the only shared copy, and it's up to 6 hours old.
- A future Discord bot ([ADR-001](001-monorepo-with-a-pure-core.md)) needs the best crafts without a browser.

## Decision

`apps/api` is a small Node server:

- **Refresh:** every 30 minutes, it asks AODP for every item the app shows, in every market, at Normal quality, on each server, through `@aoc/market-prices`' AODP client and its rate limiter. Runs never overlap. Each row keeps AODP's dates, so a price's age still counts from when AODP saw it, and the time it was fetched.
- **Storage:** Postgres, through Drizzle. One row per server, item, market and quality, in AODP's own shape. Migrations are generated by drizzle-kit and run when the server starts.
- **`GET /prices`** answers in AODP's shape, so the web app's client reads it as it reads AODP. The web app uses it when built with `VITE_PRICES_URL`, and asks AODP otherwise.
- **`GET /bestcrafts`** ranks a city's crafts with `@aoc/core`, for clients with no core of their own.
- Answers carry an ETag and `Cache-Control: public, max-age=60`. Queries are checked with Zod and get a 400 when wrong.
- Fastify, for its speed, its built-in JSON logs (pino) and its `inject()`, which tests a route without opening a port.
- The database sits behind a `PriceStore` interface, so the routes are tested against an in-memory store, and the Postgres store against a real Postgres started by Testcontainers in CI.

## Consequences

- The site is no longer only static files: the API needs a host and a Postgres database, which this decision doesn't pick.
- AODP gets one set of requests every 30 minutes instead of one per visitor.
- Only Normal quality is stored. Quality-weighted sale prices and price history still come straight from AODP.
- Saved data stays in the browser ([ADR-002](002-local-first-storage.md)). The server keeps only prices.
- The web app still works without the API, so it can be turned on by building with `VITE_PRICES_URL`.
